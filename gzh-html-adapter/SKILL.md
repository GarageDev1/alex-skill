# 微信公众号 HTML 适配

## 原则与边界

这个 Skill 只转换已有文章。原文的观点、事实、数字、单位、链接和先后顺序必须保留。

允许做的处理：

- 恢复或整理标题层级、段落、列表、引用、表格、脚注和链接。
- 拆开因文件转换而粘连的段落，合并 PDF 中的硬断行。
- 将符合条件的数据表转换为原生 HTML 图表。
- 根据文章题材和结构确定概括性的设计方向，并据此处理层级、留白、分组和颜色关系。
- 为每个元素补齐微信公众号需要的内联 CSS。

禁止做的处理：

- 补写标题、摘要、结论、过渡段、作者介绍或行动号召。
- 改写原句、调整观点顺序、删去重复内容或突出模型自行判断的重点。
- 套用固定主题库，或规定一套不顾文章内容的配色、组件和版式。
- 在正文中加入图片、SVG、Canvas、视频、脚本、外部 CSS 或外部字体。

输入含图片时，读取其中的文字、表格和可辨认数据；正文只保留提取结果、原题注、替代文字和来源链接。不得把图片写入输出 HTML。

## 产物与处理流程

每次转换交付两个文件：

1. `{原文件名}_公众号正文.html`
   - 只有一个根 `<section>`。
   - 所有样式写在元素的 `style` 属性内。
   - 不含文档外壳、按钮或脚本。
2. `{原文件名}_公众号预览.html`
   - 在正文之外提供“复制到公众号”按钮。
   - 按钮只复制正文区域的富文本。
   - 预览页的工具栏、按钮、样式和脚本不会进入剪贴板正文。

按以下顺序执行：

1. **读取输入。** Markdown、HTML、DOCX、PDF 和纯文本的处理规则见
   [references/input-normalization.md](references/input-normalization.md)。遇到扫描页或文字图片时使用中文 OCR。
2. **整理结构。** 保留原文内容和顺序，只修复标题、段落、列表、引用、表格、脚注和链接的结构。
3. **判断设计方向。** 按
   [references/design-direction.md](references/design-direction.md)
   根据文章类型、信息密度、数据比例和叙事方式确定方向。设计只改变 HTML 表现，不新增或改写内容。
4. **处理数据表。** 按
   [references/native-charts.md](references/native-charts.md)
   判断是否转为 KPI、数据表、条形图、进度图或时间线。无法从原文确认的值不得进入图表。
5. **生成正文。** 遵守
   [references/wechat-html-rules.md](references/wechat-html-rules.md)。
   根容器使用明确的浅色背景；颜色、边框和阴影服从本篇设计方向，并保持克制和一致。
6. **校验正文。**

   ```bash
   python3 <SKILL_ROOT>/scripts/validate_gzh_html.py \
     <原文件名>_公众号正文.html
   ```

   校验结果有错误时修正正文并重新运行，直到退出码为 `0`。
7. **生成预览页。**

   ```bash
   python3 <SKILL_ROOT>/scripts/build_preview.py \
     <原文件名>_公众号正文.html
   ```

8. **交付。** 先写一行 `设计方向：<方向及一句判断理由>`，再返回两个文件的路径和校验结果。这一行只出现在聊天交付说明中，不写入正文。没有执行微信公众号后台粘贴测试时，只说明结构校验通过，不声称后台粘贴已经人工确认。

## 必须避免的问题

- **把预览页当正文交付。** 公众号正文只能使用干净的 `<section>` 片段；完整文档外壳只用于本地预览和复制。
- **把 CSS 放进 `<style>`。** 微信编辑器会过滤文档级样式。正文元素必须各自带完整的内联样式。
- **漏掉文字包裹。** 可见文字必须放在 `<span leaf="">` 内，否则复制后可能丢失样式。
- **把图片换一种形式继续嵌入。** `img`、SVG、Canvas、CSS `url()`、data URI 和背景图片都属于禁止项。
- **用脚本画图。** 正文不运行 JavaScript。图表必须由普通 HTML 标签、表格结构、百分比宽高和内联 CSS 构成。
- **为了画图补数据。** 图表只能使用原文明确给出的标签、数值、单位和顺序；不插值、不估算、不补齐缺口。
- **看到数字就自动画图。** 只有结构明确的数据表才转换；正文中的零散数字保持正文。
- **把按钮放进复制区域。** “复制到公众号”按钮和状态提示必须在正文节点之外。
- **把设计说明写进正文。** 设计方向及理由只用于交付说明，不能成为文章的新段落。
- **根背景没有明确的浅色值。** 根 `<section>` 必须声明可解析的浅色纯色或浅色渐变；局部深色强调块不受此限制。
- **借适配之名改文章。** OCR 修正、断行合并和标题整理不能改变句意、数字或来源。
